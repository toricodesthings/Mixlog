# Mixlog Frontend — Agent Instructions

The app the browser runs: TanStack Start in SPA mode (`defaultSsr: false`, intentional), served by the same Worker as the server side ([`server/`](server/AGENTS.md)). It reaches data only through that side's server functions. It embodies the **Blue Hour** design language, a sibling of Cadence's Twilight Sanctuary; functional correctness and aesthetic integrity are equally non-negotiable. Everything in `src/` except `server/` follows this guide.

## 1. Non-Negotiables

- Client-rendered SPA. Do not introduce SSR assumptions: loaders run in the browser, and the shell is browser-only (`AppShell` sits inside `ClientOnly`).
- Data comes from server functions in `server/`, called from route loaders or components. File bytes are the one exception: they go through the `/api` routes, and only `lib/files.ts` talks to them (`fileUrl`, `previewUrl`, `downloadUrl`, `readFile`, and `uploadArtwork`/`uploadAudio`/`uploadLicense`, which send with XHR because only XHR reports upload progress). Never import `cloudflare:workers` here.
- Reusable hooks → `hooks/`; non-UI logic → `lib/` (client-safe, no server imports); shared UI → `components/` grouped by domain; Radix always through `components/primitives/`, never imported raw into domain components.
- **Tone.** Always fantasy, inspirational, techy, futuristic, visually striking, animated, design- and icon-heavy. Never corporate slop, complex, boring, flat or uninspiring. Cadence's sanctuary, but the room is also a studio: every surface wears an **audio-engineering cameo** or a **musical gimmick** (§6). A plain box with text in it is unfinished.
- No sterile SaaS styling: no white cards, harsh borders, file-manager grids or gray tables. Glass, mist, soft moonlit edges and breathing room; readability and usable controls take precedence over effects, and a cameo never adds a decision. Never hardcode a hex in a component: add a semantic token to `styles/app.css`.
- Musician words, never storage words (track, version, master, current; never asset, revision, active). One name per concept across the app.
- **The URL says where you are.** Anything that changes what's on screen (a page, a part, search, filter, sort, view, an open dialog or Settings) is a path or a search param, so a refresh, Back or a pasted link lands in the same place. Validate params in the route's `validateSearch`; leave defaults out. Writes stay POST server functions and never ride a link; their result lands in the URL (Save goes to the new release). Only things a URL can't hold stay in memory: picked files, a half-typed form.
- Toasts answer "where did it go?" Something that lands in place in view gets none.
- **Design by Apple's eight principles** ([HIG](https://developer.apple.com/design/human-interface-guidelines/design-principles)), read for Mixlog, and walked before any page is designed or changed: **Purpose** (the page hears the right version or ships it; its main control is that) · **Agency** (Play one tap from wherever a version shows; nothing forced, everything undoes) · **Responsibility** (say what happens to the files before it happens) · **Familiarity** (a row reads like a streaming app's: play, title, length; the same thing looks and acts the same everywhere) · **Flexibility** (thumb, keyboard and screen reader; phone and wide) · **Simplicity** (each fact once; icons and readouts over sentences; the eye reads left to right, top to bottom, most important first; detail one layer down) · **Craft** (aligned columns, tabular figures, both themes, reduced motion, seen in the running app) · **Delight** (certainty, then wonder that stays out of the music's way).

## 2. Tech Stack

React 19 · TanStack Start + TanStack Router (file routes, SPA mode) · Tailwind CSS v4 (tokens in `styles/app.css`) + `tw-animate-css` · Radix UI (wrapped) · Framer Motion (sheets and springs) · Lucide icons · `cn` (`clsx` + `tailwind-merge`, `lib/utils.ts`) · Sora + Outfit via `@fontsource-variable`, system mono for readouts · TypeScript.

## 3. Runtime Shape

- `routes/__root.tsx`: the HTML shell (fonts, `APPEARANCE_BOOT` in the head so the theme lands before first paint, `suppressHydrationWarning` on `<html>` for it), root `validateSearch` for `?settings=` and `?listen`, `component: AppShell`, `notFoundComponent: NotFound`.
- `router.tsx`: preloads on intent, restores scroll, and shows one pending page after 200ms (`releases/Pending`'s `PagePending`, which reads the URL because on a first load the outermost waiting route renders it). `routeTree.gen.ts` is generated; never edit it.
- `layout/AppShell` wraps everything in `MotionConfig` (reduced motion from Settings or the OS), shows `IconRail` or `PhoneDock`, the page `Outlet`, and `SettingsDialog`.
- The app version reaches the UI as `__APP_VERSION__` (`globals.d.ts`), defined from `package.json` in `vite.config.ts`.

## 4. Routes (`routes/`)

`/` redirects to `/upcoming`. Two sections, same shape: `/upcoming` and `/releases`, each with a release at `/<section>/$releaseId` (its Summary) and its parts under it: `/details`, `/artwork`, `/tracks`, `/tracks/$trackId`. The `$releaseId` layout route loads the release once (tracks, every version, current pins) and its parts read it with `getRouteApi`. Plus `/trash`. Settings is not a route: it opens over any page from `?settings=<tab>`. `routes/api/` holds server routes (file bytes); they render nothing and their logic lives in `server/`.

- Routes are thin: read params and search, call a loader from `components/releases/loaders.ts`, render a shared page. Business logic never lives in a route file.
- A release is Upcoming until `released_at` is stamped, then it's under Releases (`components/releases/sections.ts`: `sectionOf`, `releaseLink`, `trackLink`). A loader redirects a link from the wrong section, and a single's track URL to its Tracks part, because a single's release is its one track. A track under the wrong release is not found.

## 6. Design System (ported from Cadence)

- **Token names:** `room-*` (grounds and surfaces: `bg-room-surface`) · `ink`, `ink-soft`, `ink-muted` (text) · `line`, `line-light`, `line-strong` (borders) · `accent`, `accent-soft`, `accent-dim`, `accent-secondary`, `accent-tertiary` (the active palette; never the named `signal`/`tube`/`haze` directly) · `phantom` (the rare accent, below) · `on-accent` (text on a solid accent) · `panel`, `panel-raised` · `bg-atmosphere` (the page background) · `glow-accent` · `preview-*` (the theme cards' miniatures).
- **Porting from Cadence:** copy the file, then run `sed -i -E -f scripts/cadence-names.sed <files>` on it (and on any CSS you bring), which maps Cadence's names (`twilight-*`, `accent-primary`, `glow-lantern`, `data-cadence-*`…) to Mixlog's; then grep the file for `twilight|lantern|cadence` and map anything the script doesn't know, adding the rule to the script. Keep relative imports (`../../lib/utils`, `../../hooks/ui/…`), since the layout mirrors Cadence's; bring its CSS utilities and hooks with it; swap React Router APIs for TanStack Router ones (`useNavigate`, `Link`, `useSearch`).
- **Phantom, the unexpected accent** (`text-phantom`, `to-phantom`, `phantom-spark`; +48V magenta, `#ff6bd6` / `#a3127a`). Rare is the point: the brand mark's peak-hold dot, plus **at most one** Phantom moment per screen (the flat trace's dot on Not found; the newest bounce landing in its lane, its LED lit once; later the playhead's spark). Never a fill, a control, a feedback colour, the only carrier of meaning, or palette-responsive. Passing `phantom` to `Led`, `Meter` or `Scope` spends that screen's one moment; when in doubt, Signal.
- **The brand mark** (`primitives/BrandMark`; `public/brand/mixlog-mark.svg` and `mixlog-mark-daylight.svg` for light grounds, each with a transparent `.png`; the first is also the favicon and the app icon): *Mix·log* said aloud, five bars, the first syllable louder, its peak held in a Phantom dot, lit Signal → Haze → **Ember** (the last warm light). Its own `mark-*` tokens and `ember` (the mark's only) follow the theme, as the two files do. It sings on a `[data-meter-host]` hover or `live`. The rail and About wear it; re-render the PNGs when it changes.
- **Cameos and gimmicks** (the room is a studio; `styles/app.css` "SIGNAL GIMMICKS"). Reach for these before inventing a new one, and pick the one a real studio would use for the job:
  - `primitives/Meter`: EQ bars, still at rest, dancing while `live` or while a `[data-meter-host]` ancestor is hovered. Whatever is playing. **The signal** (`player/signal.ts`): on a desktop (no touch points: Web Audio routing can silence iPhone and iPad playback, and can't be undone), one `AnalyserNode` taps the player's `<audio>`, and while playing writes `--level-0…4`, `--bass` and `--kick` with `data-live` on every `[data-signal]` element each frame, no re-render: a live meter's bars read their bands, and the listening room's bright stars (1.3.0: the only tier that animates at all, ≤12 of them; the rest are one static layer) pulse on the kick and its halo and dark breathe with the low end (`.art-scene[data-live]` in app.css). Off under reduced motion; off, everything keeps its own dance.
  - `primitives/Scope`: an oscilloscope screen; `flat` is *no signal*. Tops every `EmptyState`.
  - `primitives/Led`: a console light, `accent` / `tube` / `phantom`, optionally `breathe`. The current destination in the rail, an upload waiting its turn, lyrics saving and a track's final; later, on-device state (with words beside it).
  - **Waiting** has three instruments, never a stock spinner or pulse: `primitives/Tuning` (a carrier racing a tiny scope) while the studio works without a file moving: a page, a save, a move, the boot screen. `primitives/Transfer` (a ring that fills, its arrow travelling `up` and out or `down` and in) for file bytes: every upload, a license being read (`readFile` reports progress), and Play while the file arrives (the player's `loading` and `readiness`; the scrubber shows what's `buffered`). `primitives/Skeleton` (a clip with the playhead's light sweeping it, staggered by `--sweep-delay`) where the shape is known: pending pages (`releases/Pending`), a cover until its artwork loads, PDF pages, a setting not yet read.
  - **The meters** (`meters/MeterBridge`, `player/LoudnessWave`): a version's loudness over the song as capsule bars on a horizon with mist below, drawn as amplitude on one fixed scale everywhere (`player/wave.ts`: 6 dB quieter is half as tall; a native range on top plays it from there), then three folds, each a card whose header (icon tile, name, one-line summary, chevron) opens and closes it: **Readings** (open: four instruments, a loudness scale, true-peak LEDs with Tube over −1 dBTP, a phase needle, the crest span, each a readout value with its change since the version before in Haze, never green or red), **Penalty** (open: every platform a row, its logo from `simple-icons` in ink, never brand colour, where it plays and the change in dB) and **More** (folded: the other readings as an icon grid). Tokens `--wave-*`, `--meter-*` in app.css "METERS".
  - `readout`: mono, tracked, uppercase, tabular lettering for version numbers, formats, timecodes, track numbers and eyebrows (`EmptyState`'s `readout`: *Ch 01 · −∞ dB*). Still musician words.
  - `signal-rule` (page header hairline), `playhead-sweep` (rows you point at), the graticule behind `bg-atmosphere`, `glass-edge` on hero cards.
- **Ported so far:** primitives `Button`, `Input`, `Switch`, `Tooltip`/`Tip`, `ScrollArea` (+ `menu-styles`), `DropdownMenu`, `SegmentedControl` (its lens glides and scrubs), `Dialog` (+ `dialog-styles`; a docked sheet on a touch phone), `SearchField`; `shared/UtilitySheet` (every compact sheet); `layout/NavigationRow`; hooks `use-shell-mode`, `use-sheet-gesture`, `use-keyboard-inset`, `use-lens-scrub`, `use-opening-release-guard`; the phone dock (`layout/PhoneDock` and its CSS) and Daylight `.glass`; `lib/constants/motion.ts` (`SPRINGS`); `settings/SettingsLayout` + `SettingRows`.
- **Surface ladder,** top to bottom: `bg-atmosphere` (ground) → `surface-deck` → `surface-shell` → `surface-card` → `surface-item` → `surface-row` → `surface-control` → floating (`surface-dialog`, `surface-floating`). Tints are tuned per mode only in `app.css`, never per component.
- **Modes:** Daylight is `data-theme="daylight"` on `<html>`, reduced motion `data-motion="reduced"`; every surface must work in both themes and with reduced motion. Z-index only through `.layer-*`.
- **Layout and input** come from `useShellMode()` only (`isDesktop`: wide and laptop; `isCompact`: tablet and phone; `isTouch`), never raw breakpoints, `matchMedia` or `innerWidth` in components. A bottom sheet is touch-only.
- **Motion** takes its feel from Apple's Liquid Glass (glass that answers a hand with a soft spring, light that follows the pointer, nothing stiff, nothing showy), built by Emil Kowalski's rules (ease-out, short, interruptible, transforms and opacity only, hover only on a fine pointer, leaving faster than arriving). It comes in two kinds. *State motion* explains what opened, moved or changed: springs from `SPRINGS`, sheets and menus a fast CSS ease-out. What follows the pointer is a short, strong ease-out tween, never a spring (`TWEENS.FOLLOW`, 200ms): a list's hover is one light that glides to the row you point at (`useHoverSlide` in `primitives/`), never a background per row: the release parts, the Upcoming and Releases list, a Summary's tracklist and signal path, the settings menu. A card you point at is glass (`.glass-card`): it rises on `--spring-liquid`, leans from the pointer, carries a specular light, and its cover drifts forward. *Ambient motion* is the room alive (meters, scope pulse, LED breathe, playhead sweep): CSS keyframes in `app.css` on `transform`/`translate`/`opacity` of an HTML box (Chrome composites those only there: the same on an `<svg>` or inside one restyles and repaints every frame, so the scene's moving parts are HTML over its SVG), slow, decorative, never meaning-bearing, never delaying an action, and every loop's resting frame is a good still (the global reduced-motion rule lands on it). Flourishes are musical, never generic: no confetti, no rewards.
- **Access:** hit targets ≥ 44×44px on touch; icon-only controls need `aria-label` + `Tip`; never `outline-none` without a replacement; never state through colour or motion alone. One meaning, one Lucide icon on every surface (Upcoming `CalendarClock`, Releases `Disc3`, Trash `Trash2`, Settings `Settings`); the brand mark is `BrandMark`, not an icon. Every cameo is `aria-hidden`; what it shows is also said in text or `aria-*`.

## 7. Shell and Pages

- `IconRail` on desktop (icons; expanded with labels, kept per device in `mixlog.rail.expanded`) and `PhoneDock` on compact: Cadence's floating glass dock (`.mobile-dock`, a pill with a gap to the bottom edge, in the layout under the pages), icons with a `Tip` and `aria-label`, its active tab a glass lens (`.dock-lens`, `use-lens-scrub`) that glides on a route change and on touch scrubs under the finger, letting go there to go; Settings is its last tab, lit while its sheet is open. The mini player rides on top of it; scrolling a page down tucks the dock into its current tab with the mini player beside it (`use-dock-tucked`: back on scrolling up, at the top, on a tap or a page change; tabs and tucked tab fade and slide, never scale, so the lens measures true). Both read `lib/nav.ts`, the one list of destinations: Upcoming, Releases, Trash; Settings sits with them as `SETTINGS_ENTRY` but opens over the page. Nothing else lists destinations. Under `pnpm dev` only, the rail adds a Developer menu (Fresh samples, Wipe everything; `server/dev.ts`); a build drops it.
- Every page is `layout/Page`: `title` plus `crumbs` (the pages above it, never itself; desktop shows the trail, compact only the way back up): Upcoming › Blue Hour EP › Track. `lead` sits before the title (a release's cover), `meta` under it (its `MetaLine`).
- **Upcoming and Releases always have two forms, Panels (the default) and List** (`releases/ReleaseList`), and always search (title, every word), filter (format) and sort above them. Search, format, sort, view and the open Upload dialog are all in the URL (`?q=&format=&sort=&view=&upload`, `listSearch` in `browse.ts`), so a refresh, Back or a link keeps them; defaults are left out. The logic is `releases/browse.ts`, pure and unit-tested.
  - **Every release wears its cover** (`ReleaseArt`): its current artwork (its small WebP preview; only the Artwork part loads the original, `full`), or a monogram pressed from the title's first letter in the title's own hue. On a row it sits before the title like a streaming app's track row; on its own page it's the header's `lead` (`ArtworkButton`). **One artwork per release, and only through its cover:** click the cover, or drop a PNG or JPG right on it (`hooks/ui/use-drop-target`, on the release page and in the new-release dialog); a new one replaces the old. An image dropped anywhere else is left out with the reason.
  - **The date** is the day it was started in Upcoming and the day it went out in Releases (`releaseDay`, `dateLabel`, through `lib/time.ts` in the device's zone): *Started Oct 12*, *Released Oct 12*. Never a clock time.
  - **Facts** follow in a `MetaLine`, split by lit dots (one truncated line in a row; `wrap` in a header, whole facts moving to the next line with no dot starting it): date · format · tracks · length (each track's final, else its newest master, else its newest mix, added up). An unknown fact is left out, never shown as zero.
  - **Both take music.** Files dropped anywhere on the page (`use-file-drop`; the `DropOverlay` arms the input, the screen's Phantom moment) or picked from **Upload** open `uploads/NewReleaseDialog`: a new release on Upcoming, one already out on Releases (it also asks the day it went out, today by default). Dropping never saves: images are left out (artwork goes on the cover), the filenames suggest the title, format (one song a single, two to four an EP, five or more an album) and where each bounce lands, through the shared `LaneMenu` (`uploads/suggest.ts`: its lane or alternate, and each song's newest lossless master as its final), shown and correctable; on Releases every file is its track's final, and tests or a second final are left out with the reason, and only **Save** creates the release, then sends the artwork and bounces one at a time with a light and words per file. A single's files are versions of its one track; on an EP or album, files with the same title are one track. A failure keeps what made it and **Try again** sends only the rest.
  - **List** is one card of rows: cover, title, facts, chevron. **Panels** is a grid of compact cards (as many across as fit): the cover, title and date, then lit icon chips (format, tracks, length). Each fact is said once per form.
- **Inside a release** (`releases/ReleaseLayout`): its own room (`.art-room`: the artwork's hues, read by `scene/palette.ts`'s `useRoomStyle`, retint the grounds and the accent of everything inside; the rail, dock and player keep Signal, and only hue and chroma come from the artwork, so contrast holds), its cover, title and facts, and its parts. With room (`isDesktop`) the parts are a panel beside the page, whose header (level with the page's) holds the cover, title and facts, leaving the page's header the way back up and its actions; without, the page's header holds them and the parts are a strip of tabs under it. The list pages never show it, and it never lists other releases.
  - **Summary** (`ReleaseSummary`): the release as its own place, never a dashboard, edge to edge (`Page`'s `bleed`: the header keeps only the way back and floats with the part tabs, `bar`, over the sky; the scene says the title as the h1). A night that's the song's own (1.3.0: `scene/generate.ts`'s `sceneOf`, seeded and shaped by the first measured bounce's fingerprint, stamped once and never redrawn, the id (the track's for a single, the release's for an EP or album) adding only the sky's detail; `scene/Sky` and `scene/Land` render it): a painted fantasy valley at night in Cadence's landscape language, every colour from the artwork: two ranges of rounded peaks rising above the band into the sky, a faint band of stars and clouds high above them, the cliffs with a waterfall and the beacon keeper's hut, wooded banks running down to a still lake that holds the moon and the lamps, a village spread down one bank and farmhouses on the other, a framing tree, sky lanterns rising, its signal ridge the song's own loudness with a scope trace, the hamlet's lights and a beacon carrying the artwork's own colour; the **signal path** (`stationsOf` in `stacks.ts`: mixes → masters → final → artwork → details in Upcoming, final → artwork → details in Releases; each lit or quietly waiting, each a link to its part) floating on glass in the sky; on the ground, like a now-playing, the cover (the artwork button), the title, its facts once, **Play** (each track's `playOf`: the final, else the newest master, else the newest mix) and a strip with a segment per track; for an EP or album, the **tracklist** below like the back of a record, each row playable (a single is its track: Play is all of it). Every fact appears once. The ground row has as much room above as below, the title on the cover's top and Play on its bottom; on desktop the scene is the page's height, the land giving way before it scrolls.
  - **Details** (`ReleaseDetailsForm`, saved together on Save with `updateRelease`): Upcoming asks title, format (three icon panels, radios underneath) and a planned day; Releases adds the release day, UPC and each track's ISRC. Every track has its lyrics (`LyricsPanel`: folded to their first lines, written in place or in the full-screen writing room; Musixmatch's layout, `#VERSE` tags marked in one click by `lyrics.ts`; saved on their own as they're written by `hooks/releases/use-lyrics.ts`, Cadence's note rhythm) and its origin: Original, Cover or Remix, asked once for the release when it has one track. A cover or remix (or any track that has one) shows its license (`LicenseControl`): Add license (click, or drop a PDF or Word document on it), then the license, which opens over the form at `?license=<versionId>` to read in place (`LicenseDocument`, loaded lazily: pdf.js, or mammoth's text of a .docx in a sandboxed frame; a .doc offers Download), its earlier versions a switch away, and New version on top. Optional but the title and a release's day.
  - **Artwork & Canvas** (`ReleaseArtwork`): the cover large (click or drop, one per release), and the places held for Canvas and other material.
  - **Tracks** (`ReleaseTracks`): each track's lanes, drawn by one set of components in either section (`Lane` with its `useTrack`, `VersionRow`, `LaneMenu`; the rules are `server/lanes.ts`). **Upcoming:** lanes top to bottom, Final (one row, the master the artist filed there; empty, a slot to drop on or click, with Pick for a lossless bounce), Masters, Mixes, each folded to its newest three, with a signal trace lit up to the highest lane holding something; then Alternates (one row per kind, earlier ones folded; they don't move). A row reads **Play**, its number (a mix and a master share one sequence per song, and the final's wears an LED), what changed (its note, else its filename), then a test's flask and format, the day and time it landed (`formatMoment`), **Meters** (`Activity`: the bridge, at `?meters=<versionId>`; docked at the room's right edge on wide (header level with the page's, a patch cable from the lit row), unfolded under the row anywhere narrower, never a sheet), **Move** (the lane menu; a test's Final asks for its WAV), Download (filename and size in its tip); on a phone the number, format and time sit under the name (up to two lines, never cut to a stub), the time on its own line, and nothing runs under the buttons. A mix or master moves by the menu, a drag onto a lane (native drag and drop, with a mouse), or Alt+↑/↓; the move keeps the file and its number, the lane that won't take it dims and says why, focus follows the row and a live region says it. Each lane's **Add** (or a file dropped on it) sends into that lane, one file at a time, each a pending `UploadRow` until it lands in place. **Releases:** one row per slot, no numbers: the final and its alternates, each with Meters and **Replace** (or a file dropped on the row), confirmed on the row naming both files before the old one is erased; a track without a final shows the empty Final slot, whose final ships it. What was set aside is said once above. A single skips the track heading (the header is its track); an EP's track opens on its own (`/tracks/$trackId`).
  - The panel's foot (the header on compact) holds **Save and exit** (submits Details through its `form` id, then goes to the list; anywhere else it just goes, nothing being unsaved) and, in Upcoming, **Move to Releases** (`MoveToReleasesDialog`, at `?move`): each track's Final lane, the same `Lane` as on Tracks in its compact size (its row adds the final's loudness and true peak, a Tube LED over −1 dBTP) (so a missing final is dropped, picked or sent there), the day it went out, and what's kept, set aside and erased said once before anything moves. In Releases, while Settings keeps what didn't ship (always, when it keeps everything), **Move back to Upcoming** brings every set-aside version back. In Upcoming, wherever one track's lanes are the page (a single's Tracks, a track of an EP or album), the header adds **Upload** (`uploads/UploadDialog`, at `?upload`): where it goes (cards, a menu on compact; it starts on the lane bounced into last), then one drop zone that also picks, handed to the track's own `send` so it lands in its lane like a drop there.
- **The player** (`player/`): one `<audio>` in the shell, so navigating never touches it. Its bar docks under the pages with a mouse (what's playing, the transport and playhead, level, the listening room, stop) and on touch rides on the dock as `MiniPlayer` (a tap or swipe up opens the listening room; play/pause is its own button). The **listening room** (`?listen`) slides up over everything: the playing *song's* own night (its track's, not its release's, so an EP's listening room matches that one song, not its Summary) with a record turning at 33⅓ as its centrepiece, a quiet land (`scene-calm`), and on the ground what's playing (its version and day), its `LoudnessWave` as the playhead (the `Scrubber` until it's measured) and the transport (back and ahead 10 and 30 seconds). It renders a list of decks, so A/B (two records, one playhead) adds a deck rather than a new screen.
- Empty is normal: an empty section is `shared/EmptyState` (a scope, a `readout`, a title, one next step), never an error. Pass `flat` when there's no signal yet.

## 8. Settings

- Opens over any page from `?settings=<tab>` (`settings/use-settings-param.ts`: opening pushes, switching tabs replaces, so Back closes it). `SettingsDialog` on desktop (searchable categories; each category's `keywords` are its row titles, kept in step with the tab; `menu` maps to the first tab), `SettingsSheet` on compact (`menu` lists categories, a tab drills in, Sign out at the foot).
- Tabs live in `settings/tabs/`, registered in `SettingsContent.tsx`; each setting has one home.
- **Releases** (`tabs/ReleasesTab.tsx`): how long what didn't ship is kept after a release goes out (a week, two weeks by default, a month, or keep everything), each shorter choice saying how many set-aside versions it would erase tonight. Kept by the Worker (`getSettings`/`saveKeepDays`), not the device, because the cleanup cron reads it.
- Appearance (theme, reduced motion) is per device: `hooks/ui/use-appearance.ts` (`mixlog.theme`, `mixlog.motion`), applied to `<html>` before first paint by `APPEARANCE_BOOT`. Sign out is Access's `/cdn-cgi/access/logout` (`SIGN_OUT_URL` in `tabs/AboutTab.tsx`).
- Browser storage holds per-device conveniences only, every read and write in `try`/`catch`; anything that must survive goes through the server.

```bash
pnpm dev | typecheck | test:unit | build | preview
```

Typecheck at minimum after changes. UI changes are checked in the running app on desktop and phone widths, in both themes.

## 10. Anti-Patterns

Hardcoded hex in components · a date parsed, sliced or formatted outside `lib/time.ts`, or a clock time on screen anywhere but a version's (`formatMoment`) · Phantom twice on one screen, on a control or fill, or as feedback · a flat surface with no cameo or atmosphere · ambient motion that carries meaning, delays an action, or has an ugly resting frame · generic celebration (confetti, success fanfare) · raw `@radix-ui/*` in domain components · raw `fetch` to the Worker · `cloudflare:workers` or `server/` internals imported outside server functions · business logic in route files · breakpoints or `matchMedia` outside `useShellMode` · a second list of destinations · a page as its own crumb · a success toast for something visible in place · storage words in the UI · generic SaaS panels and tables · view state (a filter, sort, tab or open dialog) in `useState` or `localStorage` instead of the URL · editing `routeTree.gen.ts`.

## 11. Checklist

- Build: owning domain → the eight principles (§1), one answer each; no capability lost → thin route + shared page → primitives and semantic tokens → which instrument is this? (a cameo from §6; Phantom only if the screen hasn't spent it) → server function for data.
- Review the changed flow: one obvious next step (on a track, Play); keyboard and touch access; Back and Escape behave; empty, pending and error states; daylight and reduced motion; the tone check (striking, techy, musical, not flat or corporate).
- Verify with `pnpm typecheck` and the running app. Browser resizing proves layout only, not a real phone.
